## Arbiter 结论:融合解方向成立,但有 3 个敞口必须封,否则"只多了一张事后追责的纸"

opus + minimax 逐条一致。一句话病根(minimax):**所有判定权(是否上锁/grep 是否完整/测试是否缩水/是否轻量)都握在被约束的 agent 手里**;use-gross-pay 根因不是"没人写文档",是"没人查文档写了什么"。

## 逐条决议(全接受)

### ✅[Blocker·两家一致] DA1 触发自判偏向"不上锁" + 循环依赖 → grep 前置
- 上锁=多干三件,不上锁=零成本,激励单向。且循环:要 grep 才知影响面,但 grep 只在上锁后做。
- **裁决(两家同一修法)**:**反转默认**——任何 § 只要碰到"已存在、可被引用的符号/公式/字段/分支",**必须先跑 ≥1 次 grep 看命中数**,再决定上不上锁。声明"非改命中集/轻量"的代价 = 一次 grep(轻量任务几乎免费)。**这一条同时干掉 DA1 自判后门 + DA4 轻量后门。**

### ✅[Blocker·两家一致] DA2 grep 口径无人验 → 变体清单 + 反向 grep
- 作者自选 pattern,可写窄(漏 `* 0.7`/`*0.70`/跨行变体),贴出的输出内部自洽,fusion 拿残缺事实核对残缺声明,永远放行。这是 use-gross-pay 漏改的镜像。
- **裁决**:① 必须附 **pattern 变体清单 + grep 根目录 + 命中总数**;强制一条**反向 grep**(grep 保留集符号,证明它们没被主 pattern 命中);fusion 至少挑 1 条用**作者没声明的等价 pattern 重跑**。

### ✅[Blocker/Major·两家一致] DA3 design→implement 断言缩水缝 → 字面回查
- design 写"计划断言名",implement 可落成 `toBeDefined()`(断言存在≠断言值不变)或改名/缺失,无对账。
- **裁决**:implement-review 强制——design ③ 里声明的**断言关键子串(公式片段/字段名)必须字面出现在对应 test 的 assert 里**,grep design 的 ③ → 反查 implement 的 `*.test.*`,缺或降级 = Blocker。

### ✅[Major·两家一致] DA4 轻量豁免 = 第二后门,且和盲测靶自相矛盾
- 谁判轻量?agent 自报。而"轻量"判定必须在 grep 前做,grep 前根本不知影响面。且设计第七节的盲测靶("批量加后缀")正落在"轻量"话术射程内,自相矛盾。
- **裁决**:**删掉轻量豁免**。由 DA1 的"grep 前置"替代——轻量任务跑一次 grep 命中数少,自然轻。

### ⏳[Major·两家一致·需用户拍板] DA5 纯提示词 = use-gross-pay 同代,需一道"结构地板"
- 两家都指:上次也是 SKILL.md 文字要求,照样翻车。多一段文字 ≠ 多一层约束。长 context 尾端偷工率系统性升高,而"省略"当下零惩罚。
- **裁决(需你定)**:加一道**最小结构门禁**(机器验结构、非语义,与"机器验不了质量"不冲突):"改命中集类 §"必须有**非空 grep 命令 + 非空保留集断言 ID**,缺则 `task.py start` 拒。挡住"整节省略"(最省事的偷法),把偷工从"事后打回"变成"当下交不了"。**这会动 pb_gate(反转我之前'绝不碰 pb_gate'),但只验结构存在,不验 grep 是否完整/诚实(那仍靠 fusion+人)。**

### ✅[Minor·两家一致] DA6 "新增"边界模糊 → 按"是否在 switch/分发/查找表加分支"判,不按"是否新增"
### ✅[Minor] DA7 盲测有霍桑效应 + 单样本无对照 → 需旧/新模板 A/B + 不知情观测

## 诚实边界(封完敞口后仍成立)

即便全封,determined/lazy agent 仍能跑窄 grep + 写浅断言蒙混——**结构地板挡"整节省略",挡不住"浅层合规"**。后者(grep 完整性、断言深度)机器验不了,靠 fusion+人。故本设计**降低"影响面没核对"这类 bug 率(use-gross-pay 那类),不消除**。这是纯文档层 + 结构门禁的天花板,诚实。

## 需用户拍板

**DA5 那道"最小结构门禁"要不要做?** 它是两家 fusion 认为"从'事后追责'升级到'降低发生率'"的关键,但会动 pb_gate(我之前说死不碰)。它只验结构(有没有非空 grep+断言字段),不验质量,与既定原则不冲突。做=更强但多一处 pb_gate 触点;不做=纯提示词,fusion 判定"与 use-gross-pay 同代"。
