# PB Find Precedent（找先例）

## Non-Negotiable Rule

规划复杂任务时，**找先例是必经步骤，静默跳过违规**。三路降级中的任何一路产出（包括"宣告 de-novo"）都是合格结论；唯一不合格的是根本没找就开始设计。

先例优先于新设计：项目已有同构模式时，照抄结构比从零设计更快更稳，且实施 agent 的幻觉率显著更低。找先例值得多花时间。

在 Phase 1 planning 期间使用本 skill（通常在 brainstorm 的证据勘察环节内），产出写入 `prd.md` 技术备注与 `spec-review.md` 证据区。

## 三路降级流程

按顺序尝试，前一路失败才降到下一路：

### ① 仓库内先例

在当前项目里搜同构的既有实现：

- grep 关键机制词（开关名、替换、校验、同类功能名）
- 搜实现报告 / 先例库（`docs/reports/`、`docs/modules/`、归档任务目录等项目惯例位置）
- 查相似功能的 git log / 归档任务的 `design.md`

**找到候选后必须核对同构性再照抄**（见下方核对清单）。第一次找到的先例不一定是对的——曾有案例第一次找错先例、差点照错的抄，第二次才找对。有多个候选时写明排除理由。

### ② 外部先例

仓库内无先例时，向外找框架惯例 / 开源实现：

- 用 `trellis-research`（或项目配置的研究工具）查目标框架的官方模式、知名开源项目的同类实现
- 外部先例同样要过同构性核对——别人的上下文约束和你的不同

### ③ 显式宣告 de-novo

内外都没有可用先例时，**显式宣告这是 de-novo 设计**并记入 `spec-review.md` 证据区：

```markdown
- ⏳ 先例勘察：仓库内 grep <关键词> 无同构先例；外部查 <来源> 无可复用实现。
  本设计为 de-novo，已触发更严对抗审查（reviewer 数 +1 / 攻击维度全量）。
```

de-novo 是**合格结论，不是失败**——它的作用是让对抗审查知道该加压：没有先例兜底的设计，每个决策都是新决策，审查强度应相应提高。

## 同构性核对清单

候选先例必须逐项核对，三项有一项不同构就不能直接照抄（可部分借鉴，但要在规约里写明差异点）：

| # | 核对项 | 问法 |
|---|---|---|
| 1 | 数据流向 | 先例和本需求的数据从哪产生、经过谁、到哪消费？路径同构吗？ |
| 2 | 作用域 | 先例的生效范围机制（全局/局部/命中段隔离）和本需求一致吗？ |
| 3 | 触发机制 | 先例怎么被触发（UI 开关/配置/事件）？本需求的触发点结构相同吗？ |

核对结论（含 grep 证据）记入 `spec-review.md`；照抄的结构清单记入 `prd.md` 技术备注。

## 产出去向

| 产物 | 写到哪 |
|---|---|
| 命中的先例 + 同构性核对结论 | `prd.md` 技术备注（含先例路径，供实施 agent 直接读） |
| 排除的候选 + 排除理由 / de-novo 宣告 | `spec-review.md` 证据区 |
| 本任务完成后的实现报告 | 先例库（见 `pb-harvest` 的 precedent-report 骨架）——先例库随任务自增长 |

## 反模式

- **过早下"不可行"结论**：没 grep 就断言"项目里没有这种做法"。先查再断。
- **找先例只找一次就信**：第一个候选可能是伪同构。核对清单过不了就继续找或降级。
- **静默 de-novo**：没找到先例就默默开始设计，不宣告。审查压力没加上去，幻觉风险全留给实施。
- **照抄不核对**：结构像 ≠ 同构。找错先例照错抄，比不找更糟。
