# 三层打磨协议：每层四步

prd / design / implement **各自独立走一轮**。层间顺序（prd → design → implement）是提示词级推荐，不是机器门禁——事后无法验证顺序，靠自觉。每层产出一份挑刺记录（`prd-review.md` / `design-review.md` / `implement-review.md`）。

---

## ① 写初稿：先列关键不变量 / 假设

初稿开头必须有 **`## 关键不变量 / 假设`** 区，把本层"如果这条不成立就全错"的前提显式写出来。

- 不写不变量 = fusion 只能猜你的意图，猜错就空转（真实教训：3 个 Blocker 有 2 个是误读，成因就是初稿没声明假设）。
- 每条不变量给编号（INV1 / ASM1 …），后续挑刺记录可引用。
- 模板见 `draft-template.md`。

## ② 自证事实：作者供事实，先于 fusion

fusion **无代码库上下文，这是特性**——它擅长攻逻辑自洽 / 内部矛盾 / 目标-手段错位，不擅长对事实。分工：**作者供事实、fusion 攻逻辑**。所以事实缺口先自己补，别指望 fusion 替你查代码。

各层自证方式：

| 层 | 自证方式 | 证据引用形式 |
|---|---|---|
| prd | 核对需求与真实约束 / brainstorm / 既有代码一致 | 用户原话 / brainstorm 段落 / 代码路径:行号 |
| design | grep 实证设计假设（先例是否同构、影响面清单、耦合点） | 代码路径:行号 |
| implement | grep 实证执行前提（现有测试会不会翻红、常量只在哪用、引用是否悬空） | 代码路径:行号 |

**不接受"我确认了" / "应该没问题"**——证据必须可被第三方复核。高价值事实缺口往往作者自证时就发现（早于 fusion）。

## ③ 组上下文包 → 叫 fusion 挑刺 → 逐条走查

**每轮 fusion 输入 = 上下文包**，不是裸文档，也不喂全代码库：

```
被审文档（本层初稿）
+ 明写的关键不变量 / 假设（②之前写的那些）
+ 具体证据引用（代码路径:行号 / 用户原话 / brainstorm 段落）
```

载体与实操见 `fusion-howto.md`（跨厂商并行 + 主会话 arbiter；禁同会话自审；降级留痕）。opposition brief 立场必须是"推翻这份文档"，禁总体赞扬。攻击维度见 `attack-checklist.md`。

**逐条走查**（主会话 arbiter 做）：

- ✅ **采纳** — 问题成立，本层文档已改：写明改到哪
- ❌ **反驳** — 问题不成立，**必须附证据**（grep 结果 / 文件:行号 / 用户原话），"我以为"不算证据
- ⏳ **存疑** — 暂无法定论，写明验证计划；含 Blocker 级 ⏳ 时不应定稿进入下一层 / start

不批量囫囵（"都接受" / "都没问题"都是审查白跑）。

## ④ 改终稿

把 ✅ 采纳项折回本层文档，形成本层终稿。挑刺记录（`<layer>-review.md`）与终稿一起留在任务目录。

---

## implement 轮的额外约束：防复读

implement 轮**只攻 design 未覆盖的独有项**：执行顺序、回滚路径、验证充分性。为防止退化成"复制 design 轮的发现"，`implement-review.md` 的挑刺**必须显式引用 design 轮发现并标注**：

- **采纳**：design 轮已提、implement 轮沿用
- **反驳**：design 轮提了但 implement 层不适用（附理由）
- **独有**：design 轮未覆盖、implement 层新发现

这是"强制轮次耦合、防复读"，不是机器验质量。格式见 `review-record-template.md`。
