# harvest.md 证据文件格式

`harvest.md` 写在任务目录下（与 `prd.md` 同级），是 `task.py archive` 门禁（`pb_gate.py:check_archive_gate`）的校验对象。

## 门禁校验字段（最小结构契约）

| # | 校验项 | 说明 |
|---|---|---|
| 1 | 文件存在且非空 | `<task-dir>/harvest.md` |
| 2 | 含 `## 分拣` 节 | 节内为分拣结论 |

节内结论的完整性（每类一行条目，或显式写"无"）由本 skill 流程保证，门禁不做语义校验。

门禁只做结构校验。"无收获"是合法结论，但必须**显式写出**——诚实原则：宣告"无"代表回顾做过了且确实没有可沉淀项，与静默跳过有本质区别。

## 完整模板

```markdown
# Harvest: <任务标题>

date: <YYYY-MM-DD>

## 分拣

- skill: <提炼/更新了哪个 skill，或"无"（附一句为什么：如"同类操作首次出现，未达 ≥2 次判据"）>
- lore-or-spec: <沉淀了哪条坑/契约、落到哪个文件，或"无"（update-spec 已跑过的写"已由 trellis-update-spec 覆盖：<文件>"）>
- precedent: <实现报告/决议文档路径，或"无">
- memory: <写入了哪条跨会话记忆，或"无">
- none: <五类全"无"时在此显式宣告"本任务无可沉淀收获"并给一句理由；否则删除本行>

## 回顾摘要

<三五句：本任务过程中方向被纠正了几次、关键决策是什么、
哪些是下次同类任务可以直接复用的>
```

## 填写规则

- 每类条目必须指向**真实落盘的文件/记录**，不许"声称已沉淀"。写 `precedent: 已写实现报告` 不合格；写 `precedent: docs/reports/<xx>-implementation-report.md` 合格。
- `lore-or-spec` 与上游 `trellis-update-spec` 的关系：spec 级契约由 update-spec 负责，本行记录其产物路径即可；不构成契约的小教训（lore）在这里记去处。
- 复杂任务（有 `design.md`）几乎不可能五类全"无"——至少 `precedent`（决议文档 `spec-review.md` 本身就是先例资产）通常成立。全"无"时请先自问是否真的回顾过。

## 反例

```markdown
## 分拣
- 无
```

结构上可能过门禁，但没有逐类结论——五个去处每类都要给出条目或"无"，让下一个读者知道每类都被考虑过。
